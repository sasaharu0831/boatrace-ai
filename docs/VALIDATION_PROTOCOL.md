# 検証プロトコル

## 必須検査
- race_id + boat_no + snapshot_type の一意性
- 艇番は1〜6、同一レースに重複なし
- 予定発走・実発走・観測時刻はJSTに統一
- 結果、払戻、出走表、直前情報の結合率を場別・月別に出力
- 欠場、失格、F/L、中止、不成立、返還を状態コードで保存
- 欠損値は推定値で隠さず、欠損理由とフラグを保持
- 風向は方位角およびu/v成分を保存
- 外部気象の観測時刻差を weather_lag_seconds に保存

## モデル評価
- ランダム分割は禁止。ウォークフォワード時系列分割のみ使用。
- 会場別に学習・校正・閾値・買い目点数・見送り規則を評価する。
- 予測評価: logloss、Brier score、AUC、校正曲線、1着率、券種別的中率。
- 購入評価: 購入率、回収率、最大ドローダウン、返還を含む損益。
- 開始10分後の天候は予測評価から除外し、事後の関連分析だけに使う。

## 天候分析
選手、艇番、モーター、ボート、展示、開催日、会場を統制し、風速・風向・水温・気温・波高と結果の関連を場別に推定する。因果効果とは断定しない。
